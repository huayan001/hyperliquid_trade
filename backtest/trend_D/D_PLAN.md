## 0. 数据、切分与口径

| 段 | 区间（UTC 边界） | 用途 |
|---|---|---|
| TRAIN | 2023-10-01 00:00 → 2025-03-10 00:00（不含） | 阈值（分位数）、TRAIN 资格筛选 |
| VAL | 2025-03-10 → 2025-09-10 | 在合格候选中按规则选 1 个 |

- 主组合：BTC/ETH/SOL/HYPE 4 币（与已知 L0 +218.6% / MDD 51.8% 同口径）。辅助：实盘 3 币 ETH/SOL/HYPE 组合（只报告，不计入通过判定，但写进建议）。
- 回测引擎：import ../bt.py，不改其语义。L0 = `Params("L0 实盘趋势","v0", partial_r=None, **LIVE)`：趋势最多 2 仓、组合风险 ≤4%、BTC 空头风险 ×0.7、止损后 2 根 4h 冷却（实盘口径）、日 5% / 周 10% 降杠杆 ×0.5、starter 0.35 + 4h Donchian 补仓、金字塔 ≤50%；费用 taker 0.045% / maker 0.015% / 滑点 0.02%，资金费按小时（长数据资金费低于 HL，已知低估）。
- 单笔风险：bt.py 用模块常量 `RISK`（0.02）；1% 版本在运行时设 `bt.RISK = 0.01`（不改文件）。「0.5× 仓位」通过在该笔开仓执行时临时把 `bt.RISK` 乘 0.5 实现（starter、补仓目标、金字塔都按缩小后的计划满仓计算；R 单位同步缩小）。
- 分段：交易按**开仓时间**归属；收益/回撤按资金曲线在该段内的变化（段起点 = 段前最后一个权益值）。选择阶段的运行把时间线截断在该阶段末（TRAIN 阶段只到 2025-03-10，VAL 阶段只到 2025-09-10，末尾按收盘价平仓），保证选择时看不到 TEST。TEST 阶段对「选中变体 + 两个基线」做一次 2023-10-01 起的连续回测，TEST 指标取其 2025-09-10 之后部分。
- 指标定义：Sharpe = UTC 日末权益的日收益 均值/标准差 × √365（含空仓日）；CAGR = (期末/期初)^(365/天数) − 1；Calmar = CAGR / 该段 MDD；PF = 盈利交易净额和 / 亏损交易净额和（净 = 已扣手续费与资金费）。
- 允许的唯一「已知结果」运行：L0@2% 全程复现（结果已在 report_long.md 公开：+218.6% / 51.8%），用来验证子类钩子不改变 L0 结果；在选择完成前不跑 L0@1% 或任何候选的 TEST 段。

## 2. 候选 chop 开关（共 10 个 = 5 类 × 2 种模式；全部以 1% 风险为底）

判定时点：趋势开仓信号产生的那根 1h 收盘时（与 bt.py 信号同一时刻），只用已收盘数据。只作用于**新开仓**（含 starter）；已有持仓的 Donchian 补仓、金字塔、止损/出场管理不受影响。

| 代号 | 指标（每个标的自己，除 D） | chop 条件 |
|---|---|---|
| A | 日线 ADX(14)（最后一根已收盘日线） | < θ_A |
| B | 日线 Choppiness Index(14) = 100·log10(ΣTR₁₄ / (最高高−最低低)₁₄)/log10(14) | > θ_B |
| C | 4h Kaufman 效率比 ER(30) = |C_t − C_{t−30}| / Σ|ΔC|（最后 30 根已收盘 4h） | < θ_C |
| D | BTC 日线 ADX(14)（市场整体状态，所有标的共用） | < θ_D |
| E | 断路器：组合过去 30 天内已平仓趋势交易的 R 倍数之和 R30（R = 净盈亏 / 开仓时风险单位） | < θ_E |

模式：`-R` = 该笔按 0.5× 风险开仓（即 0.5%）；`-P` = 暂停，不开这笔新仓。
变体：A-R, A-P, B-R, B-P, C-R, C-P, D-R, D-P, E-R, E-P。

阈值（不做网格寻优，每类只有一个阈值，全部来自 TRAIN）：
- 先跑 B1（L0@1%）的 TRAIN 段；取其 TRAIN 内**实际成交的开仓**（按开仓时间在 TRAIN 内）在信号时点的指标值，按全部标的合并。
- 「低 = chop」的指标（A、C、D、E）：θ = 这些值的 1/3 分位数；「高 = chop」（B）：θ = 2/3 分位数。即把 TRAIN 里最「震荡」的约 1/3 入场标为 chop。
- E 额外约束：θ_E = min(1/3 分位数, 0)（R30 ≥ 0 时永不触发）。E 是时间滑动窗口，暂停模式下不会死锁。
- 指标值缺失（预热期）时视为非 chop。阈值写入 thresholds.json 后固定，HL 6 个月和 3 币辅助回测都用同一组阈值。
- 只用开仓信号时点的指标值，不使用交易结果（无标签泄露）。

## 3. 选择规则（只看 TRAIN / VAL）

1. **TRAIN 资格**（候选相对 B1 在 TRAIN 段）：TRAIN Sharpe ≥ B1 TRAIN Sharpe − 0.05，且 TRAIN MDD ≤ B1 TRAIN MDD，且 TRAIN 交易数 ≥ B1 的 50%。
2. 写 D_DEVIATIONS.md（即使没有偏离也写「无」），然后才运行 VAL。
3. **VAL 选择**：合格候选中 VAL Sharpe 最高者；差距 ≤ 0.01 时取 VAL Calmar 高者。
4. 「VAL 支持」标志：选中者 VAL Sharpe ≥ B1 VAL Sharpe。若不支持，仍把它在 TEST 上跑一次作记录，但「1%+开关」直接判不通过。
5. 若没有候选通过 TRAIN 资格：在全部 10 个中按第 3 条选一个跑 TEST 作记录，「1%+开关」直接判不通过。
6. 选择不看 TEST、不看 HL 6 个月、不看 3 币辅助结果。

## 4. TEST（只跑一次）与判定

`test_done.flag` 在 TEST 运行开始时写入；存在该文件则拒绝再次运行 TEST。

**「1% + 开关」通过标准（选中变体，全部满足才算通过）**
- T0 VAL 支持（第 3 节第 4 条）且通过 TRAIN 资格
- T1 TEST PF ≥ 1.2（TEST 内开仓的交易）
- T2 TEST 净收益 > 0（资金曲线，已扣手续费 + 资金费）
- T3 TEST MDD ≤ B1 的 TEST MDD
- T4 全程（2023-10 → 末尾）MDD ≤ 30%
- T5 全程 Sharpe ≥ B1 全程 Sharpe − 0.1
- T6 2024Q2–Q4 段收益 > B1 同段收益（亏得更少；注意该段属于 TRAIN，只是样本内证据）
- T7 实盘 3 币 ETH/SOL/HYPE 中 ≥2 个在 TEST 上净盈利（主组合回测里该币 TEST 内开仓交易的净盈亏之和 > 0）
- T8 HL 6 个月收益 ≥ B1 的 HL 6 个月收益
- T9 TEST 交易数 ≥ 40（统计意义的最低要求）

**「只改 1% 风险」通过标准（这是仓位变更，不评价优势，只评价风险）——B1 相对 B0**
- S1 全程 MDD ≤ 30%
- S2 全程 Sharpe ≥ B0 全程 Sharpe − 0.1（优势没有被口径变化破坏）
- S3 全程 Calmar ≥ 0.9 × B0 全程 Calmar
- S4 破产风险：对全程日收益做块自助（block bootstrap，块长 20 天，10000 条 365 天路径，seed=42），P(1 年内 MDD ≥ 50%) ≤ 5%，并报告 P(MDD ≥ 30%)、中位 MDD；同时报告 B0 的同一数值作对比
- S5 TEST MDD 与 HL 6 个月 MDD 均低于 B0（健全性检查）
- 另报告（不计判定）：TEST/HL 收益符号是否与 B0 相同；4% 组合上限在 1% 下是否还会约束。

**建议规则（事先写定）**
- 1%+开关 全部通过 → 建议部署 1% + 该开关。
- 只有 1% 通过 → 建议只部署 1%。
- 都不通过 → 两者都不建议（说明原因）。
